# 管理者の完了確認と精算月指定

## 決定した仕様

- IssueがClosedかつProjectのStatusがDoneなら、作業者の完了報告なしで作業完了とする。片方だけの場合は完了確認待ち。
- 未報告の固定報酬の精算月は自動決定しない。管理者が月次一覧のモーダルでIssueと精算月を指定する。
- 有効な完了報告がある場合は、既存の精算月・担当者・報酬額を維持する。承認済み固定報酬・追加支払いがあるIssueも新規指定の対象外。
- 管理者の月指定は完了確認の記録とする。報告日時は実際の登録時刻、精算月は指定値として分けて保存し、Issue URL・管理者・監査ログを残す。
- 管理者が指定するまで、作業は「完了済み」、固定報酬は「精算月の指定待ち」。月次申請・承認や支払いは従来どおり別操作とする。
- 未完了Issueへの作業者の完了報告と、過去の証跡を使う移行登録は維持する。管理者完了済みIssueには作業者の完了報告・取り下げを表示せず、直接POSTでも報告月を上書きさせない。

## 実装

完了判定を共通化し、既存のService/Repository、候補Picker、モーダルの操作パターンを使う。月指定には既存のIssue単位の重複防止と精算入力ロックを適用し、並行した報告・承認・月指定を保存直前に再確認する。指定月が承認済みなら既存の追加支払いに接続し、通常精算の保存内容は書き換えない。支払い済み月への新規指定は拒否する。

DBの登録元に `admin_confirmation` を追加し、この登録元のみ報告日時と精算月の一致制約を外す。移行登録の証跡・対象月制約は維持する。schemaからmigrationを生成し、旧データの一括登録・月の変更は行わない。

## 検証と反映

Closed/Doneの組み合わせ、管理者以外の拒否、月境界、指定月・登録日時の独立、既存報告月の維持、精算済み除外、重複提出、支払い済み月の競合、追加支払いを単体・DB・ブラウザで検証する。format、型、lint、test、test:db、e2e、buildを実行する。DB変更は後方互換を保ち、migration完了を確認してから本番で新操作を検証する。
