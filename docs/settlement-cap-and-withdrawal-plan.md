# 時間報酬の上限適用と修正申請の取り消し

## 精算ルール

- 上限超過だけを理由に月次申請・承認を止めず、時間報酬を上限の残額までにする。固定報酬・実稼働時間は減らさない。
- 上限はIssue全期間・全作業者で共有する。承認済み金額を先に確保し、未承認分は稼働月、ログ開始日時、作業者、ログIDの順に残額を充当する。同じ月を複数回表示しても、月を逆順に承認しても二重配分しない。
- 申請済み単価、完了報告の報酬方式、JST月境界分割、ログごとの円丸めを維持する。
- 承認済み精算と通知書は保存内容を維持する。既存の確定額が現在の上限を超えている場合、新しい時間報酬の残額は0円とする。
- 上限適用前の時間報酬、Issue上限、適用後の時間報酬を明細・月次一覧・承認画面・通知書に示す。申請・承認スナップショットにも説明に必要な情報を保存する。
- 未処理修正・未終了ログなど、上限超過以外の不備は従来どおり解決が必要。

## 修正申請の取り消し

- 稼働画面に本人の申請履歴を表示し、未処理の追加・修正・除外申請だけ取り消せる。
- `cancelled`状態を追加して履歴を保持する。本人・未処理の条件付き更新と監査記録を同じSQLで保存し、管理者の承認と競合しても片方だけ成立させる。
- 承認済み・却下済み申請の取り消しや、他人の申請の取り消しは許可しない。
- 希望時間を「時間・分」で表示し、取り消し中・完了・失敗を画面に表示する。取り消しはGitHub接続に依存させない。

## 修正申請の承認前プレビュー

- 月次一覧では、各未処理申請を1件だけ承認した場合の見込みを表示する。他の未処理申請は合算せず、DBへ保存しない。
- 通常支払いの現在額と、申請反映後の固定・時間報酬・税抜・税込を比較する。上限適用前の実績額と適用後の時間報酬も表示する。
- 有効な精算ルールと既存の計算器を使う。旧ルールでIssue完了月が表示月と異なる場合は、完了月の見込みと月が異なる理由を示す。
- V2では月またぎ、他の稼働への上限配分、保存済み単価、修正承認による未確定の完了報告の失効を試算に反映する。月次承認済みの通常支払いは保存結果を維持する。
- Issue情報や承認済み金額を確認できない場合は、0円で補わず確認不可とする。
- 単体テストとブラウザーで、申請が未処理のまま見込み額を閲覧できること、承認後の金額との一致、日本時間の月境界、527pxでの読みやすさを確認する。

4. 専用ローカルDBでmigration、本人/他人/処理済み/競合を検証し、実ブラウザーで上限適用と取り消し導線を確認する。
