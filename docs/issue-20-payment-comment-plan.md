# Issue #20: 支払い済み登録時の作業者向けコメント

## 目的と対象

月次精算の支払い済み登録時に、管理者が振込名義や調整内容を任意で伝えられるようにする。対象の作業者本人と管理者が月次詳細で確認する連絡であり、管理者用の内部メモ・監査ログとしては扱わない。

追加支払い、コメントだけの編集、履歴・返信・既読、メールへの掲載は対象外。既存の支払い通知書にも含めない。

## 保存と表示

- `monthly_payments.payment_comment` に nullable な text 列を追加する。既存レコードは `NULL`。
- 支払いサービスで改行を LF に揃え、前後の空白を除去した後、最大2,000文字を検証する。HTMLの `maxlength` と同じ JavaScript 文字列長を使う。空白のみは `NULL`。
- 支払日・コメント・支払い状態は、既存の版比較付きSQLと通知イベントの保存処理で一括更新する。敗者のコメントで上書きせず、通知も重複させない。
- 未処理へ戻すときは支払日とコメントを消去する。支払い予定日の変更では保持し、取消後の再登録では新しい入力を保存する。
- 管理者の `markPaid` action で受け取り、失敗時は支払日とコメントを返してフォームに復元する。登録・取消は既存の管理者ガード、閲覧は本人／管理者ガードで制御する。
- 月次詳細では支払い済みかつコメントありの場合だけ、改行を保持した通常テキストとして表示する。長い文字列を折り返し、HTMLとして解釈しない。
- メール通知の入力・保存payloadにはコメントを渡さない。上限超過は支払い保存や通知準備より前に拒否する。

## 検証と反映

サービスで入力境界・閲覧権限・通知への非掲載を、DBテストで初回保存・取消・再登録・予定日保持・競合時の勝者との一致を確認する。E2Eでは管理者／本人／他者の画面と直接POST、空欄非表示、HTMLの安全な表示、JavaScript有無の入力保持、狭い画面での折返しを確認する。

DBとE2Eは専用テストDBで実行し、format・型検査・lint・全テスト・buildも通す。Drizzle生成SQLが列追加だけであることを確認し、テストDBへ適用後に再生成して差分がないことを確認する。

本番のmigrationとVercelのGit連携デプロイは独立している。PRのCI成功後、後方互換な追加列を本番へ先行適用して読み戻し、その後マージする。mainのCI・migration・デプロイと本番表示を確認する。本番の実支払い記録をテスト目的で更新しない。
